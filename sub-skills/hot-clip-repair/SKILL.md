# 爆款片段修复 + 溯源原创 + 下载（抖音 / 快手 / 百度）

输入一个爆款视频（抖音/快手/百度链接，或本地视频文件），完成「下载 → 画质修复（可选去水印）→ 溯源原创 → 下载原片 → 授权草稿」。

## 交付方式（默认会话直出，不绑飞书）
- 结果**直接在会话里发给用户**：修复成片 mp4、前后对比图、溯源报告、原片、授权草稿。
- 文件存用户指定目录；没指定就用 `D:\豆包工作区\`（待修复放 `02_待修复`、成片放 `03_修复完成`，不存在则建）；有 `config.json` 按其 `workspace` 路径。
- 不默认上传/写飞书；用户给了链接并授权才上传，不写死。

## 输入与开工确认

用户给的可能是：① 平台分享链接；② 本地视频文件。开工前确认（缺省按默认，不阻塞）：

1. **画质档位**：默认 `standard` 增强、超分到 **1080p**；需要更高可加做 **2K（2560宽）**（用 `professional` 前先告知耗时与口径）。
2. **是否擦除叠加**：默认不擦；用户要求"去水印/去字幕/去贴纸"时才做，且必须保留产品实物标签、人物衣物印花等非水印元素。
3. **溯源严格度**：默认给候选清单 + 置信度由用户确认；用户明确要"只下载最像的原片"时，只在有高置信结果时才下。
4. **保密要求**：若视频涉及未公开产品信息，**优先本地处理**，上传任何云端前先问用户。

## 总流程

### 第 1 步：获取视频文件

- 本地文件：直接用。
- 平台链接：按平台下载，步骤与已验证选择器直接看 `hot-video-hunter` 技能的参考文件（跨技能引用）：
  - 抖音：`hot-video-hunter/references/douyin.md` 第三节（抓 douyinvod 直链）。
  - 快手：`hot-video-hunter/references/kuaishou.md` 第三节（doubao-video-extract，官方支持）。
  - 百度好看视频：`hot-video-hunter/references/baidu.md` 第二节（抓 vdept.bdstatic.com 直链）。
- 下载后先 `probe-video-metadata` 确认可解码、时长、分辨率。
- **降级**：无 ffprobe 等工具时，基于直接观察描述分辨率/时长/问题，不编造数值；无下载能力且打不开链接时，明确告知并请用户提供本地文件，不假装已下载。

### 第 2 步：画质修复（核心，按可用能力选择）

先判断当前环境有什么能力，再选择路径，**绝不假装完成了没有工具支撑的修复**：

1. **有云端增强**：先加载 `byted-mediakit-video` 并 Read 其 `references/enhance-video.md`，参数以实时 `--schema` 为准。
   - 用 `enhance-video`（standard 档）：去噪、去压缩瑕疵、色彩与清晰度增强、超分。默认 1080p，用户要更高再出 2K；成片须 H.264、30fps、保留原音频。
   - 下载云端结果到本地，抽帧目检（产品文字、人脸、液体/火焰等细节是否自然），核验分辨率/帧率/时长/音频。
   - 异步任务用 `query-task` 轮询（running 是预期，用同一 task_id 续查）。
2. **没有云端、本机有 Real-ESRGAN**：用 `scripts/upscale.bat`（或工作区 tools 副本）本地超分兜底。运算量大，**只处理用户指定的 3-10 秒关键片段**，除非用户明确要整条并理解耗时；参数与踩坑见 `references/repair.md`。
3. **两者都没有**：明确告知"当前环境无法做画质增强，需先安装 ffmpeg/Real-ESRGAN 或连接视频增强服务"，只输出问题诊断与建议，**不产出假的成片**。

经验档位（可结合实际调整）：短边 <720p 建议 2 倍超分；已达 1080p 只做降噪锐化；压缩色块明显做综合增强。参数、码率与校验清单见 `references/repair.md`。

### 第 3 步（可选）：擦除文字/贴纸/水印

- 文字类（字幕、免责声明、标题文字、竖排提示、印章文字）：`erase-video-subtitle-pro`，按区域逐框处理，云端完成后逐帧目检。
- 图形类（纯色块、爆款/热销贴纸、卡通角标、手绘标记）：云端不处理，需本地逐帧修复，方法见 `references/repair.md`，务必羽化合成、避免硬涂抹；逐帧验证后再合回音频。
- 强约束：产品瓶身标签、包装、人物衣物印花等属于画面内容，一律保留；拿不准就保留并向用户说明。

### 第 4 步：溯源原创（半自动，不保证唯一）

完整方法见 `references/origin-trace.md`，核心是"多线索交叉 + 人工确认"：

1. 抽关键帧：`extract-frames`（开头、中段、有标志性画面/人物的帧，每片 4-8 帧）。
2. 画面反搜：对关键帧用 `visual_search`（以图搜内容，找同源视频）；服务失败可换帧重试，仍失败则记录。
3. 口播文案检索：`asr-subtitles` 取逐字稿，挑最有辨识度的一句原话用 `video_search`（抖音）、`general_search`（新闻/全网）检索；百度好看视频用浏览器搜标题/口播。
4. 多平台交叉：同一画面/文案在抖音、快手、好看视频都搜，比较发布时间，最早发布者优先。
5. 判定：逐帧/逐句一致才是同源；库存片段、通用广告模板、多次转发会出现多个候选，此时给候选清单，不臆断唯一原创。
6. 输出《原创溯源报告》：每个候选的平台、账号、链接、发布时间、相似度依据（匹配的画面/文案）、最早发布判断、置信度（高/中/低）。
   - 报告结论**一律标注"待人工确认"**，不直接宣称"已确认是原作者"；无同源结果时明确写"未找到逐帧一致原片"。
   - 置信度：发布时间明确更早+画面高度一致=高；部分特征匹配=中；多次搬运找不到源头=低（低置信度时提示不建议继续深挖）。

### 第 5 步：下载原片
- 用户确认原创（或有高置信候选）后，按第 1 步的平台方法下载该原片，优先最高清晰度（百度可切 720P/1080P，抖音取 douyinvod 直链）。
- 原片已删除/私密/无法访问时，说明并保留可公开访问的转载版本链接。

### 第 6 步：授权沟通草稿（只给草稿，不代发）
- 基于溯源结果，生成一段给疑似原作者的私信草稿：说明来意、用途、合作方式（购买授权/联名/付费转载等）。
- **只生成草稿文本，不代替用户发送、不自动私信任何人**；正式发起前提醒用户再人工核实。

## 输出物（默认会话直出）
- `修复成片_<id>_1080p.mp4`（可选 `_2K.mp4`）；做了擦除时保留未擦除母版以便回溯。
- 修复前后对比图（同一时间点左右拼接，2-3 组）。
- `原创溯源报告_<id>.md`：候选清单 + 证据 + 置信度 + "待人工确认"结论。
- `授权沟通草稿_<id>.md`（不代发）。
- `原片_<平台>_<作者>_<id>.mp4`（成功下载时）。
- 每次交付前抽帧目检 + 元数据核验，确认分辨率/帧率/音频正确；并明确处理结果是成功/部分成功/失败，失败说明原因。

## 强制规则
- 画质增强、字幕擦除都走 `byted-mediakit-video`，先 Read 对应 reference 与 `--schema`，不要凭记忆填参数。
- 找原创只能给有证据的候选，严禁编造账号或链接；无同源结果时明确说"未找到逐帧一致原片"。
- 平台下载/登录/验证码走 `browser-use-automation` 与 `interaction.request_action`，不写爬虫、不绕验证。
- 下载的他人视频仅用于找原片/高清母版与合规参考，不冒充原创；**授权状态不是"已授权"前，不得建议或暗示直接拿去投放**。
- 不擦除他人视频的 Logo/水印（用户主动要求去除自己素材的瑕疵除外）、不改 MD5、不做镜像等隐藏来源的操作。
- 涉及未公开产品信息时优先本地处理，不主动上传云端。
